# CIAOMIND 产业协同网络

产品、组织、收益与技术方案，2026-11-19。与[产品与协作指针](PRODUCT_DIRECTION.md)、[开发部门职责](DEVELOPER_OPERATING_MODEL.md)一起使用。下文区分公开证据、本项目设计和演算。品牌名称仅用于分析商业机制。

## 以项目建立网络

第一种可售服务是**文化素材数字化、许可核验与样品项目管理**。先完成一项获授权的文化资源、一个打样伙伴、一个销售或展示渠道之间的交接。每次交接同时确认版本、期限、验收人和谁承担成本。实收和实际保护投入回到同一项目记录，由此判断哪些环节可以复制、哪些环节消耗现金。

商业飞轮为**核验资源 → 形成可交付方案 → 匹配制造与渠道 → 验收并回款 → 按约定分配与回投 → 沉淀模板和伙伴能力 → 下一项目**。增长单位是完成验收及对账的项目、能重复交付的节点和带来合格需求的渠道。用户数量、总成交额、服务收入与现金流分别统计。把“资本化”落实为连续可复核的履约、单位经济、权利与续约记录，以此评估是否进一步引入资本。

## 组织和谁拥有什么

| 层级 | 职责 | 决策权 |
| --- | --- | --- |
| CIAOMIND 产业协同开发部 | 维护公共标准、组织核验、分派项目、处理权限和争议，维护平台和可复用模板 | 部门负责人决定运营优先级。公司被授权人员批准合同、费用、付款与重大承诺 |
| 项目负责人 | 形成项目编号和范围，组织权利、设计、生产、市场、财务和链路交接 | 在明确授权内管理交付计划，按证据评估进入下一阶段 |
| 外部协同节点 | 按企业或机构身份提供文化资源、设计、制造、渠道、区域资源、账务核验或技术服务 | 各方按实际资质和合同对自己的交付、报价、许可和数据负责 |
| 审核与财务 | 按约定范围复核权利、质量、成本、退款及分配，处理异议和版本变化 | 权利方确认用途。客户确认验收。财务和授权人员核对账单及转账依据 |
| 开发者与 AI | 建连接器、模型评测、数据与工作流工具，协调搜索、翻译和提醒 | 调用账户按项目与用途授权。AI 的判断进入待核验项，由有权的人确认 |

节点可跨项目复用专业能力。项目里每一个任务有执行人、接收人、截止时间和版本。小团队可兼任多项协调职责。对资金和权限等高影响操作保留相互复核，当前团队只有一名已验证的管理账号时，由具备职责的第二人对相关记录完成复核后再进入需要第二人审批的阶段。

## 资源与流量如何互换

| 节点提供 | 节点收到 | 平台核验的交付 |
| --- | --- | --- |
| 文化机构、权利方和社区提供可用的资料、授权信息和保护要求 | 署名、合规曝光、约定许可收益和保护投入报告 | 权利主体、授权版本、用途、地域、期限和实际回投证据 |
| 设计与制造节点提供规格、产能、工艺、交付和维修 | 匹配到有明确用途和预算的项目、样品费用、生产订单和历史复用机会 | 收到的规格版本、样品签收、报价承诺、准时率和返工 |
| 品牌、渠道、创作者和区域伙伴提供合格客户、试销与传播 | 可用素材、可交付供给、归属明确的项目机会及按合同确定的合作报酬 | 引荐代码记录、首次经确认的有效引荐、实际促成事项、退款复核 |
| 技术、数据和财务节点提供可复用的工具、数据接口和核验服务 | 可验证的使用场景、维护需求和约定的技术或专业服务费 | 审核版本、运行结果、工单、使用量和交付记录 |

引荐实行**单层、可验证、按项目核对**。提交时可记录已核验节点的引荐链接。项目负责人根据客户确认、来源记录和是否已有同一条商机来判定归属。多人贡献可分别记为首次引荐、交付和市场支持。经济权益以合同约定的交付和实际到账为依据。注册、邀请下级、单次点击或浏览量不触发分配。

人工匹配先看许可、地区市场、产能与交期的硬条件，再看质量、历史履约和本次适配。新节点可进入试点池并以实际交付建立记录。平台自营或付费曝光明确标记，商家可更正资料和提出异议。向渠道伙伴共享归属结果和经授权的必要信息。

## 收益、分配、回投

**试点先卖确定的交付。** 文化数字化核验、生产协调和样品可以按里程碑分别报价。权利许可、制造、设计以及渠道推广各按约定收取固定费用、单件费用或实收分成。CIAOMIND 收取明确的项目管理费或平台服务费。等到频繁出现可复用的工具需求，再考虑订阅或接口用量收费。合作伙伴自行签约或开票，或者由 CIAOMIND 按已签合同提供自己负责的服务。每案明确签约主体、对客户负责的主体、开票、退货和税务责任。

项目账按币种和最小货币单位核算。先以不含税的实收为起点，扣除退款、支付和已批准的直接成本，以及合同约定的预留。扣除后的余额按签约版本分配。相同费用只进一次账，平台已经作为直接成本收取的服务不得在剩余分配里重复收。经核验的实收、退赔和交付凭证生成结算单，按合同约定窗口确认后，由有权人员执行。撤回和更正记入下一期调整，保留原有记录。

以下为欧元演算，供审合同和压力测试，不是收费标准。假定实收（不含税）12,000，退款 1,000，支付和汇兑 200，直接成本 5,800，退货或售后预留 600，可分配余额 **4,400**。示例约定分配为权利方 1,400、设计与内容 700、渠道贡献 440、平台服务 1,200、保护回投 660，合计正好 4,400。若直接成本上升 10% 且退款再增加 500，剩余 **3,320**。按示例金额固定承诺则缺口 **1,080**，应提前写清承担方、按比例调整或停止流程的条件。

保护回投记录受益机构、用途、金额或比例、期限、凭证与可披露范围。回投支出以实际支付和接收凭证确认。维修、回收、再制造和复用分别记录物品数量、处理结果、成本及下一次使用条件。经营报告记录准时交付、返工、已收款毛利、现金回收时间和保护回投结果，可据此判断哪些模式值得复制。

## 云端节点和数据流

官网「产业协同」提供八种语言的项目、文化与权利、数字化与设计、制造与修复、品牌与渠道、区域合作、经营与财务、开发者与集成入口。提交进入 Supabase 的项目审核队列，返回一个真实申请编号。CIAOMIND 管理员在 Business OS 核对情况、转成线索项目、分派任务和继续审核。合作方的机构、联系人、范围和引荐意愿核实后，管理员在节点页登记独立节点。节点生成可分享的专属链接，暂停后新申请失去该来源标记。节点登记及状态变更写审计。登记、项目权限和素材权利各自确认。

关系为**组织 → 申请 → 项目 → 任务及证据**。审核通过的合作申请可登记节点，后续申请可关联该节点。项目号、节点号、资料版本号、验收号在交接中相互对应。公开入口使用最小字段，无须上传身份文件或合同。主库地区为法兰克福，公开页用 Vercel 托管。后台按团队角色检查数据访问。应用凭证和人员权限分开，未来外部连接器须以独立应用身份及明确用途接入。双方合同和原始文化档案采用项目授权的受控存储。

下一阶段做项目事件和定向分享。事件按版本发布，包含项目号、对象、操作、时间、权限和去重键。以“已授权、已交付、已验收、已回款”这些真实状态推进下一个动作。跨节点的自动化先只读，写入、通知和结算逐项设权限，支持撤销和追查。外部节点的授权资料按项目需要细化后再开放。既有 GitHub 保存规则、接口和验收证据，Muse 可推进验证与回读任务。

## 法律与运营前置条件

- 公开展示、训练模型、衍生设计、商业制造、再授权可能需要分别许可。意大利文化资产复制场景逐项核对权利归属、馆藏方授权与适用收费。对社区及非遗资产记录持续知情同意和利益回流。[意大利文化遗产法第 108 条](https://www.normattiva.it/atto/caricaDettaglioAtto?atto.articolo.numero=108&atto.codiceRedazionale=004G0066&atto.dataPubblicazioneGazzetta=2004-02-24) · [UNESCO 非遗伦理原则](https://ich.unesco.org/en/ethics-and-ich-00866)
- 最小化收集用于评估申请的数据。允许更正来源，控制类别、访问和留存。核对已接入服务商的处理范围、数据处理条款及跨境安排。法兰克福是主库地区。[GDPR 第 5 条](https://eur-lex.europa.eu/eli/reg/2016/679/oj/eng) · [Supabase 数据处理条款](https://supabase.com/legal/customer-resources/data-processing-addendum) · [Vercel 数据处理条款](https://vercel.com/legal/dpa)
- 在提供线上消费者交易、撮合结算或多商家市场之前，按具体合同和业务角色复核交易主体、卖家识别、排序披露、争议、发票及支付服务适用范围。代收或自动分账须由具备资质的支付服务及适当流程支持。首发用工作台记录证据和人工核对。[DSA](https://eur-lex.europa.eu/eli/reg/2022/2065/oj/eng) · [P2B](https://eur-lex.europa.eu/eli/reg/2019/1150/oj/eng) · [PSD2](https://eur-lex.europa.eu/eli/dir/2015/2366/oj/eng)
